# 소스 분석 후 결함 보완 (2026-11-14)

## 배경

소스 분석에서 저장 작업 손실, 화면·코드 불일치, 쓰이지 않는 코드가 확인되어 일괄 수정했다. 결함 ①~⑥은 수정 전 코드에서 임시 테스트로 재현한 뒤 고쳤다.

사용성 보완:

- 내보내기·코드 복사의 성공/실패, 내보낼 다이어그램이 없음, 캔버스 편집을 코드에 반영할 수 없음을 화면 상단 안내로 알린다. 안내 영역(`role="status"`)은 항상 있고 내용만 바뀐다.
- 시퀀스 다이어그램 PNG/SVG는 화면에 보이는 영역·미니맵이 아니라 확대/이동 전 다이어그램 전체를 찍는다. 시퀀스 문법 검사는 `mermaid.render` 대신 `mermaid.parse`로 한다.
- 탭을 바꿔도 코드 창 숨김 상태와 되돌리기 기록이 유지된다(상위 컴포넌트가 탭별로 보관).
- 코드 입력창 안내 문구의 줄바꿈, 첫 탭과 새 탭의 기본 코드를 통일했다.
- 가져오기는 `.mmd`, `.md`, `.txt`, `.mmdf`를 받는다. 마크다운은 첫 ` ```mermaid ` 블록만 가져오고, 줄바꿈은 LF로 맞춘다.

## 동작 변경 시 참고

- 노드를 지우면, 지운 노드와 연결돼 있던 이웃 노드의 선언(예: `B --> C[Next]`에서 B 삭제 시 `C[Next]`)이 이제 코드에 남는다. 캔버스에서는 원래 남아 있던 노드이므로 코드와 화면이 일치하게 된 것이다.
- `A & B --> C` 처럼 한 연결에 여러 노드가 묶여 있으면, 현재 구현은 라벨 수정을 그 묶음 전체에 적용한다.
- 세미콜론으로 한 줄에 여러 문장을 쓴 줄처럼 연결선 해석기가 이해하지 못하는 줄은 바꾸지 않는다. 그런 줄 가운데 연결·문장 구분 기호(`--`, `==`, `-.`, `~~~`, `;`, `&`)가 있는 줄이 지울 노드나 지울 연결을 노드 ID로 쓰고 있으면, 일부만 지우지 않고 삭제 전체를 보류한다. 라벨 글자와 `title:`·`accTitle:` 줄은 판단에서 뺀다. 코드가 그대로이면 캔버스를 코드 기준으로 다시 그리고 안내를 띄운다.
- Mermaid 키워드(`end`, `subgraph`, `style` 등)는 Mermaid와 같이 대소문자를 구분한다. `End`는 노드 이름으로 다룬다.

## 검토 반영

별도 검토 에이전트의 1차 검토에서 나온 항목을 반영했다.

- 차단: 연결선을 지운 뒤 남길 노드를 찾을 때 라벨 글자(`C[Step A]`의 `A`)를 노드 ID로 오인하고 subgraph 범위를 무시함 → 문장 단위로 해석해 노드 ID만 비교하고, 같은 subgraph 안에서만 중복 여부를 본다.
- 경고: subgraph 위치 찾기가 다른 subgraph 제목에 같은 글자가 있으면 그 줄을 고름 → 정확한 ID, `[제목]`, `"제목"`, 제목 일부 순으로 찾는다.
- 경고: `A -- v1.-beta --> B` 처럼 글자가 든 연결선의 닫는 화살표를 잘못 끊음 → 여는 기호 종류에 맞는 닫는 화살표만 받는다.
- 경고: 해석하지 못한 줄에 다른 화살표가 있어도 노드 삭제 때 줄째 지움 → 연결 기호가 있는 줄은 지우지 않는다.
- 경고: 같은 노드가 맨 ID로 먼저, 모양 선언으로 나중에 나오면 선언이 사라짐 → 모양 있는 선언을 따로 보존한다.
- 제안: 반영할 수 없는 캔버스 편집·내보낼 것 없음 안내, 안내 영역 상시 유지, `extractMermaidText` 외부 공개 제거, 현재 탭 코드 저장을 실제 표시 탭 기준으로, README에 SVG 주의 문구.
- 반영하지 않음: `&` 묶음의 라벨을 연결별로 나누는 일(구조 변경이 커서 보류), README 첫머리의 "노드 이동이 코드에 반영" 문구(노드 위치는 코드에 저장되지 않음. 사용자 판단 필요).

2차 검토(반영분 재검토)에서 나온 항목:

- 경고: 키워드를 대소문자 구분 없이 판정해 `End` 노드를 지우지 못하거나 subgraph 범위를 잘못 셈 → Mermaid처럼 대소문자를 구분한다.
- 경고: `A:::hot`처럼 클래스만 붙은 노드가 연결 삭제 뒤 맨 ID로 취급되어 클래스 지정이 사라짐 → 모양·라벨·클래스가 붙은 원문은 항상 남긴다.
- 경고: 해석하지 못한 줄에 지운 노드가 남아 있는데 다른 줄의 선언만 지워져, 안내 없이 노드가 라벨을 잃고 되살아남 → 이런 경우 삭제 전체를 보류하고 안내한다.
- 제안: 삭제 안내 테스트에 캔버스 다시 그리기 확인 추가, `end;` 중첩 subgraph 테스트 추가, 주석·검증 수치 정정.
- 반영하지 못함: 연결선 라벨 수정 안내의 화면 테스트. 테스트 환경(jsdom)에서는 연결선이 그려지지 않아 라벨을 누를 수 없다.

3차 검토(2차 반영분 재검토)에서 나온 항목:

- 경고: 삭제 보류 판단이 frontmatter 제목·`accTitle`·라벨 글자 속 단어까지 노드로 보아 정상 삭제를 막음 → 라벨 글자를 비우고, 연결·문장 구분 기호가 있는 줄만 보며, `title:`·`accTitle:`·`accDescr` 줄은 뺀다.
- 경고(기존 결함): 해석하지 못한 `B[Mid]; C[Other]` 줄에서 B를 지우면 줄째 지워져 C도 사라짐 → `;`·`&`이 있는 줄은 지우지 않고 삭제 전체를 보류한다.
- 제안: 지운 노드를 가리키는 `style B ...` 줄이 남아 Mermaid가 B를 다시 만듦 → 이번에 고치지 않음(아래 남은 제한).

## 남은 제한

- 연결선 해석기는 ASCII 노드 ID(`A-Z a-z 0-9 _`)만 이해한다. 한글 노드 ID 줄은 건드리지 않는다(기존 동작과 같음).
- 같은 두 노드 사이의 연결이 여러 번 있으면 라벨 수정·삭제가 모두에 적용된다(기존 동작과 같음).
- 노드를 지워도 그 노드를 가리키는 `style`·`class`·`click` 줄은 남는다. `style B ...`가 남으면 Mermaid가 B를 다시 만든다(기존 동작과 같음).
