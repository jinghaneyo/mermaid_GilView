# v1.1.0 릴리즈 (2026-11-16)

## 내용

- 버전을 1.0.1에서 1.1.0으로 올렸다. 결함 수정과 함께 기능(가져오기 형식 추가, 화면 안내, 버전 표시)이 늘어 부 버전을 올렸다.
- 화면 탭 줄 오른쪽 끝에 앱 버전(`v1.1.0`)을 표시한다. 값은 `package.json`의 `version`을 빌드 때 읽으므로, 버전을 올리면 화면 표시도 함께 바뀐다.
- README 첫머리에 GitHub Pages 바로 실행 주소를 넣고, 릴리즈 파일 이름과 압축 안 파일 위치를 실제 패키지 구성에 맞췄다.
- 이번 릴리즈에 담긴 결함 수정 내용은 `docs/20261114/소스-보완.md`에 있다.

## 릴리즈 패키지 구성

이전 릴리즈(v1.0.1)와 같은 구성이다.

| 파일 | 내용 |
| --- | --- |
| `mermaid-gilview-v1.1.0-package.zip` | `standalone/mermaid-gilview.html`(단일 파일, 더블클릭으로 실행), `web/`(GitHub Pages와 같은 빌드), `README-release.txt` |
| `mermaid-gilview-v1.1.0-package.zip.sha256` | zip 파일의 SHA-256 값 |

- `web/`은 `/mermaid_GilView/` 경로 아래에서 제공되도록 만든 빌드다. 웹 서버 최상위 경로에 그대로 올리면 화면이 뜨지 않는다(이전 릴리즈와 같음).

## 검증

- 타입 검사 `./node_modules/.bin/tsc -b --pretty false`: 종료 코드 0
- 관련 테스트 `./node_modules/.bin/vitest run src/MermaidVisualEditor.test.jsx`: 56개 통과. 버전 표시를 지우면 버전 테스트가 실패하는 것을 확인했다.
- Pages용 빌드 `vite build`와 단일 HTML 빌드 `vite build --mode single`: 둘 다 성공. 결과물에는 버전 값만 들어가고 `package.json`의 다른 항목(의존성 목록 등)은 들어가지 않는다.
- 별도 검토 에이전트 검토: 차단 결함 없음. 버전 글자 대비가 낮다는 제안을 받아 `text-slate-400`으로 바꿨다.

## 확인된 배포 설정 문제

저장소의 GitHub Pages 원본 설정이 `main` 브랜치 최상위(legacy)로 되어 있어, 푸시할 때마다 Actions 배포(`dist`)와 브랜치 직접 배포(소스 `index.html`)가 함께 돈다. 지금까지는 Actions 배포가 늦게 끝나 정상 화면이 남았지만 순서가 보장되지 않는다. Pages 원본을 GitHub Actions로 바꾸는 것은 원격 설정 변경이라 사용자 결정이 필요하다.
